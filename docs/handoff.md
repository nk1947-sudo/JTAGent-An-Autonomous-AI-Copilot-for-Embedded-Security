## Changes made

- Added authenticated `DELETE /api/attack-lab/plans/{plan_id}`. A terminal plan returns `200 {"deleted": true}` and frees a slot; a missing plan returns 404; a nonterminal or in-use plan returns 409. Deletion removes only the plan from process memory. It does not touch runs, edge evidence, hardware state, or exported files.
- Execution and bundle export mark plans in use before waiting for the shared target lock. Deletion checks use before and after acquiring the lock. The capacity check now runs just before insertion after configuration awaits, preventing concurrent creation from exceeding 20 plans.
- Attack Lab loads saved plans so an operator can select an older plan after reload, confirm deletion, see pending and error states, and keep the selected plan on failure. Switching plans clears the previous plan's bundle result. The dialog distinguishes plan-held evidence from raw bytes retained separately by the edge.
- Added API and Playwright regressions. Regenerated `contracts/openapi.json`, `web/src/api.d.ts`, and build-time validators. Updated the existing root `IMPLEMENTATION_PLAN.md` in place. All prior worktree modifications were preserved.
- Fixed the mock browser stack's port allocation to avoid Chromium-blocked ports, with bounded high-port fallback and collision retry. Readiness now requires the isolated stack's health token, including on Windows where the virtual environment launcher and service have different PIDs. Stack cleanup leaves unrelated listeners running.
- The edge ledger now reclaims definitive results only after their session has expired or disappeared. It retains uncertain results, charges capacity before operation budgets, and records cancellation results so a state-changing request cannot be replayed after a lost acknowledgement. Raw evidence retention is unchanged.
- Failed and cancelled snapshots now retain acquisition attempts with actual partial evidence, error and restoration state. Final status read failure marks the target state uncertain and requires reconciliation; reports and bundles carry the failure record.
- Logout cancels that login's active audit tasks and revokes its edge sessions. Edge revocation serializes with operations, restores a held mock lease within three seconds, and requires operator reconciliation if restoration fails. A failed edge revocation returns HTTP 503 after local signout; the edge session then expires by its TTL.
- Operator workflow browser coverage now exercises scoped investigations, progress/evidence, report and bundle exports, reopening and switching retained runs, deletion, and signout. The dashboard clears local evidence on a 503 revocation result or expired login and discards responses that arrive after signout. Existing Attack Lab browser coverage exercises retained plan switching and deletion.
- Added local Ollama inference for an already installed model. It accepts loopback HTTP only, checks the model digest before each typed request, bounds input/output/time/response size, and records provider-returned token counts. Scripted and Nebius adapters remain available. Failed analysis now retains any reported usage and measured latency in the run.
- Hardened the in-scope Nebius adapter: requests have a 30-second total deadline, responses are streamed under a 1 MB cap, malformed model catalogs fail closed, usage keeps only nonnegative provider token counts, and mismatched returned model identity is rejected when the API supplies an identity field. `model_id` is the catalog-visible/requested model ID where the provider omits a served-model field.
- The existing single retry for selected transient HTTP statuses remains bounded. A retryable server error may still duplicate billable work if the provider completed the first request before returning that error; no automatic provider fallback is configured.
- The dashboard now shows the selected run's requested inference model, and its investigation test checks that identity in the JSON report.
